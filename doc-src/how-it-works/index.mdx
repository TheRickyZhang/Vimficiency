A session hands the optimizer an initial buffer, a goal buffer, the cursor, and
what you typed. Finding something shorter is two problems, solved in order.

<figure class="vf-figure">
  <TwoStages />
  <figcaption>Partition first, then search. The partition is priced by a coarse keystroke heuristic; the search re-prices the winning sequence with exact Vim semantics.</figcaption>
</figure>

1. **Partition** the change into planned edits: which runs of the initial text
   to delete, which runs of the goal to type, and where to move in between.
2. **Search** for the cheapest keystrokes that carry out each planned edit,
   over editor states with exact Vim semantics.

These chapters walk through both. Every widget in them runs the real planner,
compiled to WebAssembly from the same C++ the plugin ships, so you can type your
own initial and goal text and watch the numbers change.

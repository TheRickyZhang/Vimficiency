• Current Status
  TreeDiff::calculate() does not yet contain the real DP. It currently builds:

  Tree initialTree(initialLines);
  Tree goalTree(goalLines);

  then emits one whole-buffer replacement. The DP should replace that placeholder with a planner that returns a forward,
  non-overlapping vector<DiffState> in original-buffer coordinates.

  What The DP Is Solving
  This is not generic tree edit distance. The goal is:

  > choose a clean ordered list of replacement regions that round-trips exactly and has low estimated edit cost.

  Each output diff is conceptually:

  replace initialTree.text[oldBegin:oldEnd]
  with    goalTree.text[newBegin:newEnd]

  Then convert that flat replacement into DiffState.

  The tree is just the structure used to choose natural replacement boundaries:

  Root -> Paragraph -> Line -> BigWord -> Word -> Char

  The DP must still be exact: if higher-level grouping does not line up, the Char level always gives an exact solution.
  That is not a fallback; it is the base case.

  Tree Contract
  The DP can rely on these invariants:

  - Tree::text is the flattened buffer.
  - Each Node::text is a half-open flat text range.
  - Each Node::children is a half-open range into the next level vector.
  - Children are ordered and contiguous in text.
  - Levels are fixed-depth.
  - Char nodes are leaves.
  - The output diffs must be in forward document order.
  - Positions in output diffs are against the original initial buffer.

  The most useful primitive is a boundary function:

  boundary(parentText, childRange, k)

  Meaning “the flat text position before child k.” For a child range [begin, end):

  - if k < end, boundary is children[k].text.begin
  - if k == end, boundary is parent.text.end

  This is essential for pure insertions and EOF edits.

  Core Solve Shape
  Use a recursive sequence solver:

  solve(level, oldParentText, oldChildRange,
               newParentText, newChildRange) -> Plan

  It compares two sibling lists at the same level.

  At root, you call it on root children, so it compares paragraph lists. When comparing line nodes, it compares BigWord
  children, and so on.

  A Plan should contain:

  cost
  diffCount
  trace/reconstruction data

  For actual implementation, avoid storing vector<DiffState> in every DP cell. Store cost plus parent/action traces, then
  reconstruct once at the end.

  DP States
  Use two main states:

  OUT(i, j)
  IN(i, j, delState)

  Where:

  - OUT: we are not currently building a replacement diff.
  - IN: we are inside one contiguous replacement diff.
  - i: next old child index.
  - j: next new child index.
  - delState: needed only if deletion cost saturates.

  The indices are local offsets or absolute child indices. Local offsets are usually easier for table indexing; absolute
  indices are easier for boundaries. Either is fine, but pick one and be consistent.

  Why IN Exists
  Without IN, you would have to try every arbitrary range:

  old[i:i2] -> new[j:j2]

  That is expensive and awkward.

  With IN, contiguity falls out naturally:

  open diff
  consume old/new children while inside
  close diff

  The path itself defines the replacement span.

  Transitions
  In OUT(i, j):

  1. Keep identical child:

  oldChild.text == newChild.text
  OUT(i, j) -> OUT(i + 1, j + 1)
  cost += 0

  2. Recurse into paired internal nodes:

  OUT(i, j) -> OUT(i + 1, j + 1)
  cost += solve(childLevel, oldChild.children, newChild.children)

  Only do this when both nodes have children. For Char, there is no recursion.

  3. Open a replacement:

  Do this as an edge into IN, but avoid zero-progress cycles. The cleanest way is for “open” to immediately take one
  consume action, or to carry an IN flag that disallows immediate close before consuming anything.

  In IN(i, j, delState):

  1. Consume old child only:

  delete old[i]
  IN(i, j) -> IN(i + 1, j)

  2. Consume new child only:

  insert new[j]
  IN(i, j) -> IN(i, j + 1)

  3. Consume both:

  replace old[i] with new[j]
  IN(i, j) -> IN(i + 1, j + 1)

  4. Close replacement:

  IN(i, j) -> OUT(i, j)
  emit one replacement span

  Close is valid only after the active diff consumed at least one old or new child.

  Cost Model
  For the first implementation, keep this deliberately simple.

  Insertion cost:

  inserted byte count

  Deletion cost at a level:

  min(deletedUnits * deleteCost[level], deleteCost[parentLevel])

  or whatever constants you settle on.

  Split penalty:

  +1 per emitted diff

  Charging the first diff too is fine. For a changed buffer, every valid solution has at least one diff, so “per diff” and
  “per extra diff after the first” differ only by a constant. It avoids needing a seenEdit state.

  Recursive plan cost:

  cost += childPlan.cost

  A recursive plan contributes however many diffs it reconstructs. If it has zero diffs, it is effectively a keep.

  Important delState Caveat
  If deletion cost saturates, IN(i, j) alone is not enough.

  Example:

  min(k * wordCost, lineCost)

  Two paths can reach the same (i, j):

  - one has deleted 0 old units
  - one has already deleted enough to saturate at lineCost

  Consuming one more old unit has different marginal cost. So IN needs either:

  delState = deletedUnitsCapped

  or

  delCostSoFarCapped

  Because the cap is small, this should be a tiny dimension.

  If you temporarily use pure deleted-byte cost, you can skip delState, but with the saturation heuristic you need it for
  exactness.

  Replacement Span Reconstruction
  When closing an IN block, reconstruct:

  oldBegin = oldBoundary(blockStartI)
  oldEnd   = oldBoundary(currentI)

  newBegin = newBoundary(blockStartJ)
  newEnd   = newBoundary(currentJ)

  Then create:

  EditSpan{oldBegin, oldEnd, newBegin, newEnd}

  Later convert to DiffState.

  This handles all cases:

  - replacement: old span non-empty, new span non-empty
  - deletion: old span non-empty, new span empty
  - insertion: old span empty, new span non-empty

  Pure insertion uses oldBegin == oldEnd.

  DiffState Conversion
  For each reconstructed span:

  deletedText  = initialTree.text.substr(oldBegin, oldEnd - oldBegin)
  insertedText = goalTree.text.substr(newBegin, newEnd - newBegin)
  beginPos     = DiffText::flatIndexToPosition(oldBegin, initialTree.text)
  endPos       = DiffText::advancePositionByText(beginPos, deletedText)
  boundary     = TransformBoundary(initialLines, beginPos, endPos)

  Then:

  DiffState(beginPos, endPos, deletedText, insertedText, boundary)

  Skip exact no-op spans.

  Recursion Semantics
  The DP has two ways to handle a changed pair of nodes:

  1. Recurse into children and possibly produce smaller diffs.
  2. Treat the whole region as part of an outer replacement block.

  That choice is the whole point of the algorithm.

  Example:

  abcd -> acdb

  At word/char level, it may choose one larger replacement instead of multiple tiny edits if the split penalty makes that
  cheaper.

  For tokenization changes like:

  aa aa -> aaaa

  the parent sequence DP must still work because IN can consume multiple old children and one new child, or vice versa.

  Exactness
  Exactness comes from these facts:

  - Every tree node owns a contiguous text range.
  - The tree decomposes down to chars.
  - IN can consume old-only, new-only, or both.
  - Therefore any old text can be transformed into any new text at char level.

  So there should be no “fallback to Myers.” If the DP cannot solve a case, the DP is wrong.

  Ordering
  TreeDiff should stay forward-only for now.

  CompositionSearchContext currently preserves Myers’ old reverse-order heuristic only for Myers. TreeDiff should return
  diffs in document order. The later OriginalDiffMapper and calculateLinesAfterDiffs() machinery expects original-buffer
  coordinates and handles sequential position shifts.

  Implementation Shape
  I would build this in layers:

  struct EditSpan {
    TextRange oldText;
    TextRange newText;
  };

  struct SolveResult {
    int cost = INF;
    int diffCount = 0;
    int traceRoot = -1;
  };

  Then internal DP tables:

  out[i][j]
  in[i][j][delState]

  Each cell stores:

  cost
  previous cell
  action
  optional child solve id

  Actions:

  Keep
  Recurse
  OpenAndDelete
  OpenAndInsert
  OpenAndReplace
  DeleteMore
  InsertMore
  ReplaceMore
  Close

  You can avoid a separate Open action by making opening consume immediately. That keeps the graph acyclic and avoids empty
  active diffs.

  Tests To Add First
  Before tuning costs, pin round-trip and shape behavior:

  - no change -> no diffs
  - one char replacement
  - pure insertion
  - pure deletion
  - two far-apart edits split into two diffs
  - nearby same-word edits prefer one diff
  - whitespace-only edit
  - aa aa -> aaaa
  - paragraph replacement
  - empty buffer and final newline
  - random property: applying TreeDiff diffs equals goal

  The first milestone is not “best possible diff”; it is “exact, forward, non-overlapping, round-trippable, and
  structurally capable of grouping.”
